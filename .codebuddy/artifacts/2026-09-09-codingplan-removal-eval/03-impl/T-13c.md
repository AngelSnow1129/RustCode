### 1.2 `crates/rustcode-tuix/src/commands.rs`（2 处描述 + 3 行说明注释）

- `:194`（原 `:191`）`login`：`desc: "Sign in with OAuth and claim CodingPlan models"` →
  `desc: "Managed sign-in (distribution builds only) -- this open build uses bring-your-own-key providers; configure config.toml"`
- `:219`（原 `:216`）`usage`：`desc: "Show CodingPlan usage (tabs: current / overview / models)"` →
  `desc: "Show token usage (tabs: current / overview / models)"`
- `:191-193` 新增 3 行注释，说明 `desc` 只是 fallback、真值由 `cmd_desc_i18n()` 在渲染期按 `managed_login_available()` 选版；`:218` 新增 1 行注释指向 `Msg::CmdDescUsageNeutral`。

**中性变体确认存在**（无需新增 i18n 变体）：
- `rustcode-config/src/i18n/messages.rs:2283` `CmdDescLoginNeutral`、`:2304` `CmdDescUsageNeutral`
- `rustcode-config/src/i18n/en.rs:1619-1620`（login neutral 文案）、`:1639-1640` `"Show token usage (tabs: current / overview / models)"`
- `rustcode-config/src/i18n/zh_cn.rs:1562-1563`、`:1580-1581`（中文 neutral 文案）
- `crates/rustcode-tuix/src/commands.rs:303-309 / 325-331` 中 `cmd_desc_i18n()` 已按 `managed_login_available()` 在 `Msg::CmdDescLogin(Neutral)` / `Msg::CmdDescUsage(Neutral)` 之间选版。

**实现偏差声明（1 处，已最小化）**：`Command::desc` 的类型是 `&'static str`（`commands.rs:5`），`BUILTIN_COMMANDS` 是 `const`，无法在其中引用 `Msg::CmdDescLoginNeutral` 枚举值（i18n 需运行时 `t()`）。因此采用「**使用中性变体的确切文案**」而非「引用变体标识符」，并用注释显式锚定来源以防漂移。两条 `desc` 在运行时实际是死路径：`cmd_desc_i18n("login"/"usage")` 恒返回 `Some`，`help_text()`（`commands.rs:113-114`）与 ACP（`commands.rs:398`）都优先取 i18n 结果，静态 `desc` 仅在 i18n 缺失时兜底 —— 故**本次改动在 discovery 面零可观测行为变化**。

## 5. 遗留风险与后续项

1. **`modals::provider_panel::tests::codingplan_models_are_read_only_in_the_panel` 失败（基线既存）**：建议由 `provider_panel.rs` / `rustcode-config` 的归属任务处理 —— 要么在中立构建下修正 `is_codingplan_provider_name` 的前缀判定，要么给该用例加 `#[cfg(feature = "codingplan")]` 门控。负责人建议：P3 系列中负责 `rustcode-config` 或 `modals/provider_panel.rs` 的任务。本任务未越权修改。
2. **静态 `desc` 与 i18n neutral 文案存在字面重复**：受 `&'static str` + `const` 限制无法引用枚举，已加注释锚定来源。若后续 `Command::desc` 改为 `Cow<'static, str>` 或 `Msg`，可直接改为引用 `Msg::CmdDescLoginNeutral` / `Msg::CmdDescUsageNeutral` 消除重复。
3. **任务单计数与仓库实际不符**：任务单称 `render/mod.rs`(3)、`render/retained.rs`(3)、`render/qr.rs`(1)、`render/cell.rs`(1)、`sanitize.rs`(1) 共 9 处，实测基线均为 0。若上游评估口径是别的关键词（例如中文「套餐」也已为 0），建议复核评估脚本，避免后续任务重复派工。
4. **并行中间态**：`cargo check` / `cargo test` 执行时 P3a 正在大改 `event_loop/commands.rs` 与 `event_loop/mod.rs`，结果可能随其中间态波动；当前结论基于上述输出，必要时在 P3a 合入后重跑一次。
