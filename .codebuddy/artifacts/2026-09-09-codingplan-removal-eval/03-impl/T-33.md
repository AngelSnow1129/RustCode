## 2. search-index 判定：**生成物，不手工编辑**

判定证据（三条互相印证）：

1. 存在生成脚本 `site/build-search-index.mjs`，写出路径即目标文件：`site/build-search-index.mjs:202`
   `const outFile = path.join(DOCS_DIR, `search-index.${lang}.json`);`
2. `site/package.json:7` 注册了对应 npm script：`"build:search": "node build-search-index.mjs"`
3. 两个 JSON 均为**单行**（`JSON.stringify(out)`，无换行、无缩进）：grep 每文件恰好 1 匹配即整行，148.7 KB / 139.1 KB —— 非人工可维护形态。

**生成命令**（供编排者执行）：

```bash
cd /workspace/RustCode/site && node build-search-index.mjs      # 等价: npm run build:search
```

**本次未执行**，原因：任务硬性约束「禁止执行 cargo / npm 命令（本目录是静态站点，无需构建）」。

**重新生成时的注意点（重要）**：该脚本除写 JSON 外，还会把缺失的 heading anchor id **回写进 HTML 源文件** —— `site/build-search-index.mjs:188-192`：

```js
if (newMain !== main) {
  await fs.writeFile(filePath, html.replace(main, () => newMain));
  injectedFiles++;
}
```

因此重新生成后 `git diff` 会额外出现 HTML 里 `id="..."` 的新增，**需人工 review 后再提交**，不要直接 `git add -A`。

**该产物已被 git 跟踪**（`git ls-files` 命中 `site/docs/search-index.en.json` / `.zh.json`），所以「不重新生成就提交」会把含 codingplan 的旧索引带进版本库 —— 这是本任务唯一的**未闭环项**。
