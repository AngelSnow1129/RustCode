**行为变更（持久化语义）**

- `logical_accounts()`（改前 797-816）：取消"折叠为合成账号"，改为**每个 `[providers.*]` 条目一个
  同名账号**（`out.insert(name.clone(), project_legacy_account(p))`），无分组、无"首个胜出"语义。
  已写入用户配置文件的 `RustCode` / `RustCode-anthropic` / `RustCode-ollama` / `AtomGit-*` 条目
  仍是合法条目，照常加载，只是不再折叠、不再受只读保护。新 schema `provider_accounts` 仍在
  id 冲突时胜出。
- `logical_models()`（改前 859-887）：account 恒为原名（`project_legacy_model(name, p)`），
  不再调用 `effective_reasoning_effort_levels`；`models` 分支改为直接 `m.clone()`。
- `provider_config_for_selection()`（改前 1036-1040）：同步移除
  `effective_reasoning_effort_levels` 调用，legacy 分支只保留 `clamp_effort_to_levels`
  （与识别层无关，保留原语义）。
- 内置 effort levels：`declared` 为空即视为**不受限**（沿用既有 `allowed_effort_levels`：
  `None`/空 ⇒ 全部 `REASONING_EFFORT_LEVELS`），不再回退到内置档位表。

无 `#[allow]`、无 cfg 兜底、未削弱任何无关断言。

**注释清理（同文件）**：`logical_accounts` doc、`logical_models` 内联注释、
`upgrade_legacy_provider` 注释、`provider_config_for_selection` doc、

## 5. 遗留风险与后续项

1. **`endpoints.rs` 生产方仍在**：本文件对其引用已归零，但其 `is_codingplan_llm_gateway` /
   `codingplan_provider_prefix` 及 `:262` 处指向 `config::is_codingplan_provider_name` 的文档引用
   仍存在，归**下一任务**删除。若并行任务同时改动该文件导致编译错误，不在本任务范围内，
   请勿在 T-23a 内修改。
2. **持久化语义变更的用户可见影响（已授权）**：既有 `RustCode*` / `AtomGit*` 条目从
   "合成分组账号 + 只读"变为"独立可编辑账号"。此前依赖"改一个即改整组"折叠行为的用户，
   升级后需逐条修改。建议在 P7 全部完成后的发布说明中提示。
3. **`deepseek-v4-flash` 等模型不再被客户端限档**：服务端未下发 `reasoning_effort_levels` 时
   客户端不再收窄为 `[high, max]`，用户可选全部 5 档；若服务端实际不支持某档会在请求层报错。
   属预期行为（以服务端声明为准），需服务端侧确认已下发该字段。
4. **未触碰的既有 warning**：见 3.2 / 3.6，均位于 `files_owned` 之外，建议由对应模块负责人
   单独清理，不在本任务顺带修复。
