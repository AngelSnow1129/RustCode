## 2. 持久化语义变更清单（用户 Q2' 授权；不迁移、不改写用户磁盘）

config.toml 的 **schema 与键名完全不变**，旧文件照旧解析；变的是"语义解释"。以下逐条：

1. **账号折叠消失**
   - 行为：旧逻辑把 `[providers.RustCode]`、`RustCode-GLM-5.2`、`RustCode-anthropic`、`AtomGit-*` 等
     按 wire format 折叠成共享合成账号 `RustCode` / `RustCode-anthropic` / `RustCode-ollama`；
     现在**每个 `[providers.*]` 键投影成同名账号**，model 也归属同名账号。
   - 对既有 config.toml：`logical_accounts()` / `logical_models()` / `resolve_model(..).account_id`
     返回的账号 id 由"分组 id"变为"provider 键名"（如 `RustCode-anthropic` 不再变成 `RustCode-anthropic`… 旧折叠下 openai 组模型会归到 `RustCode`）。
     磁盘字节不变；引用分组 id 的 UI/日志/后续任务需改用 provider 键名。

2. **`AtomGit` legacy 前缀兼容消失**
   - 行为：不再有"历史前缀仍被识别"的集合（`LEGACY_CODINGPLAN_PREFIX` + 前缀匹配规则整体删除）。
   - 对既有 config.toml：磁盘上已有的 `AtomGit-*` / `AtomGit` 键**仍正常加载、可解析、可用**，
     只是降为**普通自定义 provider**（不再只读、不再折叠、不再被 `/login` 自动接管）。不改写文件。

3. **内置 effort 回退消失**
   - 行为：删除 `codingplan_builtin_effort_levels`（`deepseek-v4-flash` → `["high","max"]`）。
     `effective_reasoning_effort_levels(declared)` 现在：非空 declared 列表 → 原样采纳；否则 `None`（= 不限制，5 档全开）。
   - 对既有 config.toml：若某模型**未**持久化 `reasoning_effort_levels`，旧逻辑在"判定为托管网关"时会注入 `[high, max]`，
     现在一律 `None` → UI 显示全部 5 档，且 `clamp_effort_to_levels` 不再把用户持久化的 `medium` 夹成 `None`。
     注：默认构建里网关判定恒为 false（HOSTED 值为空且无 env），因此对绝大多数用户无实际差异。

4. **"签名网关"识别整体消失（endpoints 侧，本轮）**
   - 行为：`is_codingplan_llm_gateway()` 删除 → 没有任何 `base_url` 会被判为托管/签名网关，所有 provider 一律纯 `bearer_auth(api_key)`。
     默认构建本就恒 false（默认值为空），故**非行为回退**，只是不再存在"显式配置即可打开"的开关。
   - 环境变量（非 config.toml）：`RUSTCODE_CODINGPLAN_API_BASE`、`RUSTCODE_CODINGPLAN_LLM_BASE_URL`、
     `RUSTCODE_CODINGPLAN_PROVIDER_PREFIX` **变为无效**（设置不报错，直接被忽略）。

5. **没有**任何 config.toml 键被删/改名/迁移，也没有静默 fresh：所有变化都是只读投影层与解释层。
