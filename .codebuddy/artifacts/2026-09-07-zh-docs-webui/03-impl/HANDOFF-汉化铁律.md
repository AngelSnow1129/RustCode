# 汉化任务共享铁律（D-10 及以后各批共用）

所有汉化任务（D-xx）**必须逐条遵守**本文件。派发时只给「files_owned 清单 + 本批特殊说明」，其余以此文件为准。

基线 `ZH_BASE=3ee655e3`。自检工具 `scripts/check-zh-docs.py`。

## 1. 目标

把文件的**英文正文**译为简体中文。**纯中文替换，不做中英并列，不保留英文原文段落。**

## 2. 八条铁律（违反即判 FAIL）

1. **不翻译** fenced code block（``` 或 ~~~ 包裹）内任何内容 —— 含注释与字符串，一个字符都不动。
2. **不翻译** inline code（反引号包裹）内任何内容；**也不得**把原本不在反引号里的词改成反引号（会破坏 AC-4 的 code span 多重集相等）。
3. **保留原文**：文件路径、目录名、crate 名（`rustcode-*`）、命令与 CLI flag、环境变量（`RUSTCODE_*`）、配置键/TOML 表名、HTTP 方法与 API 路径、`Msg::Xxx` 变体名、枚举变体、函数名/类型名/工具名/hook 名、第三方专有名词（OpenAI、Anthropic、Ollama、Rust、Tokio、VS Code、ACP…）、版本号/日期/数字。
4. **不改**链接目标与锚点，只可译显示文字。
5. **不改**文件名、不改标题层级。
6. **不新增** Unicode Emoji；也**不**顺手清理已有 Emoji。
7. **YAML frontmatter**：若文件首行为 `---`，键名（`name`/`description`/`kind`/`id`/`status`/`decision`/`from`/`to`/`feature`/`requires`/`created`）**一律保留英文**；`description` 的值可汉化，但**必须在报告中逐条列出**（AC-6）。
8. **已中文的段落不润色、不改写**，只处理英文段落。

## 3. 若文件已是大段中文

只处理 `check` 报出的英文 offender 行（多为英文标题/术语/结构性标签）。
若 `en/total <= 0.05` 则记 **no-op**，**不得**改写已中文段落。

## 4. 必做自检

```bash
python3 scripts/check-zh-docs.py check --base 3ee655e3 \
  --report .codebuddy/artifacts/2026-09-07-zh-docs-webui/03-impl/zh-check-<任务ID>.md \
  --files <本批文件相对路径，空格分隔>
```

每文件每项都要 PASS：

- **AC-2** `en/total <= 0.05`
- **AC-4** inline code + fenced code 集合与改动前**完全相等**
- **AC-7b** `](...)` 链接目标多重集**相等**
- **AC-32** Emoji 数**不增加**

**若 AC-4 或 AC-7b FAIL，说明误改了代码或链接，必须改回到 PASS。**

## 5. 前批实测踩过的坑（务必规避）

1. **把普通词误包成反引号** → AC-4 FAIL（D-05、D-07 各踩一次）。
2. **全角括号/全角标点包裹的英文词**（如「（event_loop）」「Expected: PASS。」）：全角字符不在脚本的 CJK 判定区间内，仍被算作英文行 → AC-2 残留（D-06、D-08、D-09 均踩）。**必须补入真实汉字**，不能只加全角标点。
3. **批量替换波及代码块** → AC-4 FAIL（D-07 踩）。改后务必立即复检。
4. **多插/少删空行**会破坏「纯行内替换」口径（D-06 踩）。保持 `+N/-N` 行数相等。
5. `--report` 会**覆盖**已存在的报告文件：手写小结必须在**最后一次**自检之后追加（D-08 踩）。
6. **跨行反引号对**（D-10、D-14 踩，最隐蔽）：原文硬折行会把一对反引号拆到两行，基线因此**不生成** code span，反而把英文散文误算成 inline code。若你把它重排成一行，AC-4 立刻 FAIL。**必须保留原折行位置与反引号位置**，只译自由散文。代价可能是个别英文词残留，属白名单，报告写明即可。
7. **行数判定**：允许总行数因中文更紧凑而减少（如 151→144），**关键判定是 AC-2/4/7b/32 而非行数相等**；但**不得**增删空行改变段落结构（D-06 曾多插一个空行）。

## 6. 报告要求

- 路径 `03-impl/zh-check-<任务ID>.md`
- 脚本自动段之外，**手写中文小结**：每个文件改动量（含 no-op 判定）、残留行清单及「为何属于白名单」、四项实测结果
- **严禁**「（待填）」「（实现后补全）」等占位符 —— 出现即判假成功
- 报告用中文

## 7. 边界

只改 `files_owned` 内的文件。不执行 `cargo`/`npm` 构建与测试（纯文档任务）。不改源码。
