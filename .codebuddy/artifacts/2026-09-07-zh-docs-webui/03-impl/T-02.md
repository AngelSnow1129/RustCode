## 5. 遗留风险与后续项

1. **契约未分化 mode 的前置检查（建议 SA 裁决，本轮未擅自改）**：`--if-missing` 且 dist 已存在时，若环境无 node/npm，脚本仍 exit 2 而非跳过。`01-design.md §4.2` 的 exit 2 定义未按 mode 分化，故保持现状。若希望「已有产物 + 无工具链」场景下也能静默跳过，需 SA 修订契约后由本任务改 `:150-200`。
2. **`engines.node` 范围写法只校验下界**：`parse_node_min()` 取第一个版本号（如 `>=22.6 <24` → `22.6`），上界不校验。当前 `webui/package.json` 为 `>=22.6`，无影响。
3. **`npm ci` 会重建 `node_modules`**（本轮实测删除并重装 158 packages）。这是 `AGENTS.md:16` 要求的 `npm ci` 口径，但意味着脚本不是离线可用的；离线场景需依赖 E3 的 `--if-missing` 提示。
4. **`cargo clean -p rustcode-daemon` 的实际效果未在本任务验证**：脚本只负责提示（E8 原文即为「主动提示」）。「清理后 `cargo build` 确实内嵌新 dist」属集成验收，建议由 `test-engineer` 在 T-06 覆盖。
5. **AC-17 / E7 属 T-05**（`Msg::CliWebuiNotBuilt` 文案），本任务未涉及，需确保 T-05 文案中的命令与本脚本口径一致（`npm ci`、`cargo clean -p rustcode-daemon`）。
