### 4.2 与 rustcode 内置能力的撞车（`rustcode-parallel-review`）

- 冲突：rustcode 已内置 `code_review` 子 agent 工具（`crates/rustcode-coding/src/parts.rs:608`）
  与 TUI `/review` 斜杠命令（`crates/rustcode-tuix/src/event_loop/commands.rs:1785`，
  `/review <base>` 表示 `<base>..HEAD`）。直接照搬 OMO 的 review-work 会变成重复造轮子并互相打架。
- 处理：正文首段用**分工表**写清三者关系，并把"不替代内置审查"写成硬约束——
  内置审查没跑就先跑内置，本技能结论叠加在其上；子代理一律 `explore`（只读），
  不派 `worker`，本轮不改代码。
- 附带：OMO 原名 `review-work` 与内置 `code_review` 语义过近，故改名为 `rustcode-parallel-review`。

### 4.3 与 `AGENTS.md` 的规范对齐（未发现冲突，主动对齐而非照搬 OMO）

- `remove-ai-slops` 的类别定义直接采用 `AGENTS.md` 硬约束：禁 Unicode Emoji、ASCII 标签
  （`[INFO]`/`[CHECK]`/`[ERROR]`/`[+]`/`[-]`）、`thiserror` + `anyhow` 强类型错误、禁裸 `unwrap`/`expect`。
- `refactor` 补入 `AGENTS.md` 的依赖方向（`kernel` <- `capabilities` <- `coding` <- `tuix` <- `cli`），
  禁止反向依赖；`git-master` 补入"禁止 `sudo` 运行"。
- OMO `programming` 技能主张的 250 行 LOC 上限、绝对禁 `unwrap` 等与本仓口径**不一致**，
  故该技能未在本批采纳（定级为"需改造后可行"，见 `01-import-plan.md` §3.2）。

### 4.4 任务书给的事实与实测不一致（已按实测修正）

- 任务书写"`frontend`（2.9MB，含 19 个 CSV 知识库）"：实测 `du -sh` 为 2.9M 无误，
  但 CSV 数为 **24** 个（位于 `references/ui-ux-db/data/`），且另有

- 任务书写"`lsp-setup`：rustcode 无 LSP 工具"：实测 rustcode-coding 默认带 `lsp` feature
