Quickstart

Install RustCode, run the first-time wizard, and complete your first task in a few minutes.

Requirements

  • OS: macOS (Apple Silicon or Intel), Linux, Windows, or HarmonyOS PC
  • Rust toolchain: 1.75+ (only required when building from source)
  • LLM: an API key for any supported third-party provider (bring your own key)

Install

Option 1: install script (recommended)

This build ships no built-in download host. Obtain install.sh from your distribution channel (the release page of whoever distributes rustcode to you), then point the script at that channel's release host:

# macOS / Linux / HarmonyOS PC
RUSTCODE_RELEASE_BASE=https://example.com/your-host/releases/download sh install.sh

The script downloads the prebuilt binary for your platform and places it at ~/.local/bin/rustcode (or /usr/local/bin when that is writable). Make sure that directory is on your PATH.

On Windows PowerShell, obtain install.ps1 from your distribution channel and run:

$env:RUSTCODE_RELEASE_BASE = 'https://example.com/your-host/releases/download'
powershell -ExecutionPolicy Bypass -File install.ps1

It downloads the Windows x64 prebuilt binary and updates PATH; open a fresh terminal to use the rustcode command.

Option 2: install using npm

If you already have Node.js 18+ installed, install globally with npm:

npm install -g @rustcode/rustcode

The package uses optionalDependencies to pull the prebuilt binary for your platform (macOS x64 / arm64, Linux x64 / arm64, Windows x64, HarmonyOS arm64) — one command, cross-platform.

Option 3: install using Homebrew

If you have Homebrew installed, install the cask (macOS x64 / arm64, Linux x64 / arm64):

brew install --cask rustcode

The cask downloads the prebuilt binary for your platform and links it to your PATH automatically.

Option 4: build from source

Get the source from your distribution channel, for example:

git clone https://example.com/<your-org>/rustcode.git
cd rustcode
cargo build --release
cp target/release/rustcode ~/.local/bin/

Release builds take longer to compile but produce a small, fast binary. For day-to-day development a plain cargo build is fine.

Verify the install

rustcode --version

You should see something like rustcode 5.0.x (build-id).

Shell completion (optional)

RustCode can generate command and option completions for common shells:

rustcode completion zsh
rustcode completion bash
rustcode completion fish
rustcode completion powershell

Load the generated script using your shell's normal setup. This affects CLI completion only; inside the TUI, Tab completes input and Shift+Tab cycles execution mode.

Your first task

cd into a project you know, launch rustcode, and just describe what you want:

cd ~/projects/my-web-app
rustcode

> give me a brief overview of this project's directory layout and tech stack

RustCode autonomously:

  1. Runs list_directory, read_file, and similar tools to explore the code;
  2. Identifies key descriptor files (package.json / Cargo.toml / …);
  3. Returns a structured summary.
Tip

Not sure what to ask? Try: "fix every typo in the README", "add TypeScript types to the functions in src/utils.ts", "run the tests and fix any failures".

Uninstall

When you're done with RustCode, the built-in uninstall subcommand cleans up in one shot. It asks group-by-group whether to delete: the binary plus the PATH edits the installer made, credentials such as ~/.rustcode/auth.toml, and runtime state such as ~/.rustcode/sessions/.

Interactive (recommended)

rustcode uninstall

Each group prompts y/N with a sensible default (binary = yes, credentials = no, state = yes) — pressing Enter is a reasonable choice.

Non-interactive

# Fully automatic: take the default decisions, no prompts
rustcode uninstall --yes

# Wipe everything (including the entire ~/.rustcode/ directory)
rustcode uninstall --purge

# Only remove the binary and PATH edits; keep ~/.rustcode/ intact
rustcode uninstall --keep-data

# Just print the plan; do nothing
rustcode uninstall --dry-run
Heads up

--purge also deletes all session history, memories, and custom provider configs. It is irreversible. If you might use RustCode again, prefer the interactive default or --keep-data.
