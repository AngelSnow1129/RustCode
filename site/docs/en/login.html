Provider credentials

RustCode is bring-your-own-key (BYO) by default: point it at any third-party LLM provider with an API key and you are done — no account, no login, no external platform. Credentials live locally in ~/.rustcode/config.toml (or ~/.rustcode/auth.toml for some OAuth-based providers). This page covers how to configure them.

Managed sign-in has been removed

The optional distribution-provided managed sign-in (/login) and its account / quota system were removed on 2026-09-09. The open-source build has always been BYO; the managed path no longer exists in any build. Configure a provider below instead.

Configure a provider

To use your own OpenAI / Claude / DeepSeek / GLM key, there are three ways:

Option A: /provider in the TUI

  1. Type /provider in the TUI.
  2. Choose a third-party provider preset or a custom endpoint, enter its API key, then add one or more models under that account.
  3. The configuration is written back to ~/.rustcode/config.toml.

Option B: hand-edit the config file

Edit ~/.rustcode/config.toml directly and add a [providers.*] entry; see ProviderConfig fields.

Option C: one-shot CLI override

Don't want to touch the config file and only need a different provider for one run? Add flags at launch:

rustcode --provider deepseek --model deepseek-reasoner

Running fully offline? Configure a local Ollama provider — no key and no login required.

Check status

rustcode status     # or /status in the TUI — shows current provider and model
