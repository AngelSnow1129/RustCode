Headless & Daemon

In addition to the interactive TUI, RustCode offers two non-interactive modes: -p headless on the CLI for scripts and CI, and rustcode-daemon — an HTTP + SSE API service that any client can drive.

Headless CLI mode

Add -p / --prompt to rustcode to execute a single task and write the reply straight to stdout (like Claude Code's -p mode):

rustcode -p "give me a brief overview of this repo"

By default only the AI's final reply text goes to stdout — handy for piping. Tool calls and token usage are kept out of stdout.

Common headless flags

FlagDescription
-p, --prompt TEXTTask description to run
--prompt-file PATHRead the prompt from a file (good for long input; mutually exclusive with -p)
-v, --verboseSend tool-call logs, token usage, and turn summaries to stderr; stdout is untouched
--max-turns NHard cap of N LLM calls — keeps the agent from running away. No cap by default
--disable-tools LISTDisable specific tools, e.g. bash,web_fetch. Disabled tools are absent from the schema list so the model won't try to call them
-C, --dir PATHWorking directory; defaults to the current directory
--provider / --modelTemporarily override provider or model
--no-telemetryAccepted and ignored - this fork ships no telemetry

Examples

# Generate a project summary and write it to a README draft
rustcode -p "summarise the project structure and produce a README draft" > README.draft.md

# Auto-fix lint errors in CI
rustcode -p "run pnpm lint and fix every error; don't modify test files" \
         --max-turns 30 --disable-tools web_search,web_fetch

# Read the prompt from a file
rustcode --prompt-file task.md -v 2> run.log

# Local Ollama, completely offline
rustcode -p "explain this code" --provider local --model qwen2.5:14b

Exit codes

  • 0 — normal completion
  • Non-zero — an error occurred. The error message goes to stderr; details are in the -v log
Note: permission model

Headless mode has no interactive permission dialog. In the current implementation, bash calls that would prompt are auto-approved, and the reason is written to stderr:

[headless] auto-approved bash: <reason>

Other tools that would prompt for confirmation (edit, write, high-risk paths for web_fetch, …) are auto-denied:

[approval-denied] tool=<name> reason=<reason>

When [approval-denied] fires, the process exits with a non-zero code. If you don't want shell execution in CI, add --disable-tools bash explicitly to remove it from the tool list entirely.

rustcode-daemon

rustcode-daemon is a standalone transport adapter over CodingRuntime. It exposes an HTTP + Server-Sent Events API for web frontends, IDE plugins, and editor extensions. The official RustCode VS Code extension and the RustCode Air desktop app both connect through it.

Launching

# Recommended: launch via the CLI subcommand — it invokes the sibling rustcode-daemon binary
rustcode daemon

# Pick a port and client identity (drives local client-mode branching)
rustcode daemon --port 13456 --client vscode

# You can also invoke the daemon binary directly (more options)
rustcode-daemon --host 127.0.0.1 --port 13456 \
                --client rustcode-air --idle-timeout 1800

The daemon reads the same ~/.rustcode config as the CLI — provider credentials and configuration, plus session history, are all shared (distribution builds additionally share managed-account login state).

Launch flags

FlagDescription
--host HOSTListen address; default 127.0.0.1. Non-loopback addresses trigger a warning (the daemon has no auth and must not be exposed publicly)
--port PORTListen port; default 13456
--client NAMEClient identity; currently vscode / rustcode-air are recognised, anything else is treated as a generic IDE. Affects local client-mode branching and some behaviour
--idle-timeout SECSIdle timeout in seconds. Default 1800 (30 min); 0 disables it; non-zero values are clamped to a minimum of 60. Also accepts the env var RUSTCODE_DAEMON_IDLE_TIMEOUT
--no-telemetryAccepted and ignored - this fork ships no telemetry
Security

The daemon has no built-in auth and binds 127.0.0.1 by default. Never expose it to the public internet or to your LAN directly — callers gain full execution rights for every tool on your machine (including bash, write, edit). For remote access, terminate at a reverse proxy that handles auth / TLS / origin restrictions.

Auth (managed sign-in removed)

The optional distribution-provided managed sign-in was removed on 2026-09-09. No current build ships a managed service, so there is no account system or OAuth flow. Configure third-party providers with your own API key via the Config / providers routes above (POST /providers) or ~/.rustcode/config.toml. The /auth/* sign-in routes are retained as no-ops: GET /auth/status reports managed_available: false and the WebUI hides its account/sign-in surfaces; POST /auth/login/start fails fast with 501 (managed_login_unavailable, non-retryable). The /codingplan/* routes were also removed on 2026-09-09 and return 404 in every build.

Method + PathDescription
GET /auth/statusAlways reports managed_available: false in the current build (no sign-in service). The WebUI hides its account/sign-in surfaces rather than offering a login that can only fail.
POST /auth/login/startNo-op — returns 501 with error code managed_login_unavailable (non-retryable), steering clients to bring-your-own-key provider setup
POST /auth/login/:login_id/pollNo-op — part of the removed managed sign-in flow
DELETE /auth/login/:login_idNo-op — part of the removed managed sign-in flow
POST /auth/logoutNo-op — part of the removed managed sign-in flow

SSE streaming chat

The SSE stream returned by POST /chat includes events for AI text deltas, reasoning deltas, tool-call batches (start / end), token stats, errors, and more. The daemon wire schema is defined by LiveWireEvent in crates/rustcode-daemon/src/live_api.rs.

Frontends can consume the stream with the native EventSource or any SSE client library.

CORS

The daemon configures CORS to allow only loopback origins: the host must be localhost, 127.0.0.1, or ::1 (any port, any protocol). Other origins are rejected. This is defence in depth alongside the default --host 127.0.0.1 bind — even if someone tries DNS rebinding to forge a request, the CORS layer still blocks it.

Typical uses

  • Editor plugins / IDE extensions (VS Code, JetBrains)
  • Desktop GUIs (e.g. the official RustCode Air)
  • Self-hosted local web UIs (move the terminal agent into the browser)
  • Local script orchestration: dispatch multiple tasks over HTTP, share session history
