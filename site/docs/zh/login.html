常见问题

供应商凭据

RustCode 默认采用自带密钥(BYO)方式:填入任一第三方 LLM provider 的 API Key 即可使用 —— 不需要账号,也不需要登录,更没有外部平台。凭据保存在本地 ~/.rustcode/config.toml(部分基于 OAuth 的 provider 存在 ~/.rustcode/auth.toml)。本页说明如何配置。

托管登录已移除

原发行版可选的托管登录(/login)及其账号 / 额度体系已于 2026-09-09 移除。开源构建自始就是 BYO;任何构建都不再存在托管登录路径。请改用下面的 provider 凭据配置。

配置 provider(BYO)

如果你想使用自有的 OpenAI / Claude / DeepSeek / GLM 等密钥,有三种做法:

方式 A:TUI 内 /provider

  1. 在 TUI 中输入 /provider。
  2. 选择第三方 provider 预设或自定义端点,填写 API Key;然后在该账号下添加一个或多个模型。
  3. 配置会自动写回 ~/.rustcode/config.toml。

方式 B:手动编辑配置文件

直接编辑 ~/.rustcode/config.toml,写入一个 [providers.*] 条目即可,字段参见 ProviderConfig 字段。

方式 C:命令行一次性覆盖

不想改配置文件、只想临时用另一个 provider?启动时加参数即可:

rustcode --provider deepseek --model deepseek-reasoner

完全离线使用?配置一个本地 Ollama provider —— 不需要密钥,也不需要登录。

查看状态

rustcode status     # 或 TUI 内 /status — 显示当前 provider 与模型
